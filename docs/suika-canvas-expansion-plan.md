# Suika как редактор экрана: расширение по образцу Canvas

**Статус:** фазы A, B, C и D сделаны в коде (14 октября 2026).  
**Дата:** 14 октября 2026.  
**Рядом:** [`suika-herald-integration-plan.md`](suika-herald-integration-plan.md) (остров `/suika/`, сохранение PNG, фазы 0–3 уже сделаны), [`enterprise-slide-editor-plan.md`](enterprise-slide-editor-plan.md) (слой постера отдельно от слайда с живыми данными), [`scenify-studio-plan.md`](scenify-studio-plan.md) (Studio остаётся вторым островом), [`canva-editor-embed-plan.md`](canva-editor-embed-plan.md) (чужой Canva, не наш холст).

«Canvas» в этом документе — встроенный редактор постера, каким его делает ScreenCloud: галерея макетов под размер экрана, портрет и альбом, блокируемые зоны, «сохранить как шаблон команды», правка уезжает на уже стоящие экраны. Это не сайт Canva и не HTML-элемент `<canvas>`. Живые данные (календарь, погода, таблица) Canvas туда не кладёт — для них отдельные приложения. У нас ту же границу уже держит инвариант I1: Suika рисует файл в библиотеке, слайд с `{{ds}}` остаётся другим документом.

---

## 1. Решение коротко

1. **Suika остаётся генератором картинки.** Плеер по-прежнему получает PNG (или JPEG). JSON бумаги `.suika` лежит sidecar и нужен только чтобы открыть тот же макет снова. На экран JSON не уезжает.
2. **Не строить второй редактор слайдов внутри Suika.** Переговорка, повестка, меню с ценой из таблицы — это Слайды. Suika закрывает то, что Canvas закрывает у ScreenCloud: акция, афиша, объявление, меню-картинка, заставка лобби.
3. **Холст уже умеет рисовать.** В ядре есть фигуры, текст, картинка, перо, кадры, страницы, замок слоя, выравнивание, snap, undo. Расширение — не новые примитивы, а контур signage: размер экрана, галерея своих макетов, бренд воркспейса, режим «заполни, не двигай», публикация в уже играющий ролик.
4. **Чужие галереи не копировать.** 140 шаблонов ScreenCloud и тысячи OptiSigns — их рисунки. Свой набор начинается с 12 макетов, нарисованных в Suika и лежащих в репозитории как `.suika`.
5. **Studio (`/studio/`) не выключать и не сливать с Suika в этом плане.** Оба острова пишут в библиотеку. Новый функционал вешается на Suika, потому что именно её открывает «Создать дизайн».
6. **Бренд-кит уже есть** (`GET/PUT /api/brand-kit`: 4 цвета, 2 шрифта каталога, логотип). Suika его не читает. Первая поставка подключает его, а не заводит второй набор цветов.

## 2. Что Suika умеет сегодня

Остров собран по плану интеграции (сентябрь 2026). Кнопка в библиотеке видна только если `HEAD /suika/index.html` отвечает (I5). Окно открывается на `/suika/?mode=herald`. Сохранение шлёт PNG и бумагу в `POST /api/studio/export` с пометкой редактора `suika`. Повторное открытие грузит sidecar по `contentId`. Фон слайда возвращается в Слайды через `suika.slideBgReturn`.

| Уже есть | Где | Чего не хватает для Canvas |
|---|---|---|
| Инструменты: выбор, кадр, прямоугольник, эллипс, картинка, перо, карандаш, линия, многоугольник, звезда, текст, рука | `apps/suika` тулбар, `packages/core/src/tools` | Набор фигур достаточный. Нет палитры «элементов вывески» (иконки, плашки цены) |
| Страницы | `components/Pages` | Экспорт в Herald берёт только текущую страницу |
| Замок слоя, выравнивание, snap, поворот, undo | слои, `AlignCard`, `snap` | Замок дизайнерский: его можно снять. Нет режима «филиал заполняет текст и фото» |
| Три размера | `herald/presets.ts`: 1920×1080, 1080×1920, 800×480 | Нет полосы, квадрата, 4K, безопасной зоны ТВ |
| Белый лист на размер пресета | `blankPaperForPreset` | Галерея макетов — фаза B, сделана |
| Картинка с диска | `tool_draw_img` | Нет выбора из библиотеки Herald |
| Шрифт в бумаге | атрибут `fontFamily`, в спайке `sans-serif` | Нет шрифтов каталога с кириллицей. В PNG глиф запекается, поэтому на экране шрифт не нужен, но в редакторе без файла кириллица будет «тофу» |
| Бренд | — | `/api/brand-kit` не вызывается |
| Сохранить в библиотеку / править тот же файл | `herald/bridge.ts` | Нет «сохранить как шаблон команды». Замена файла обновляет библиотеку; отдельно надо убедиться, что экран, который уже играет этот `content_id`, подхватывает новые байты без нового плейлиста |

Инварианты, которые расширение не ломает:

| ID | Следствие |
|---|---|
| I1 | Suika не пишет `template` / `fields` слайда. Единственный мост в слайд — уже сделанный фон (`for=slide-bg`) |
| I4 | После сохранения экран играет файл с диска Herald. Выключенный редактор ничего не останавливает |
| I5 | Новые кнопки («Шаблоны», «Заполнить») скрыты, если остров не собран |

## 3. Что взять у Canvas и чего не брать

| Приём Canvas | Берём | Как у нас |
|---|---|---|
| Макеты под физический экран, альбом и портрет | Да | Пресет задаёт холст. Список шире трёх размеров, но конечный |
| Галерея внутри редактора, не отдельный сайт | Да | Первый экран режима `herald`: пустой лист или макет |
| Свой набор, не пак конкурента | Да | 12 бумаг в репозитории, потом шаблоны воркспейса |
| Lockable areas | Да | Слой с `heraldLock`, режим Fill не снимает замок и не двигает объект |
| Save as template для команды | Да | Шаблон воркспейса, позже организации. Это JSON бумаги, не PNG |
| Правка уезжает на экраны | Да | Повторное сохранение того же `content_id` подменяет байты, плейлист не пересобирают |
| «Забудьте сторонние редакторы» как единственный путь | Нет | Canva-ingest остаётся отдельным планом для тех, кто уже рисует там |
| Живые виджеты погоды и календаря на холсте | Нет | Это Слайды и виджеты зон. Иначе два автора одного экрана |
| 140 готовых картинок в первом релизе | Нет | Двенадцать своих. Число на сайте не обещаем, пока пак не нарисован |

## 4. Продукт по фазам

### Фаза A — холст знает, что он экран

**Сделано.**

Оператор по-прежнему может начать с пустого листа. Лист сразу размера экрана, с полями бренда и безопасной зоной.

**Пресеты — сделано.** К трём текущим добавлены, старые id не менялись:

| id | Размер | Зачем |
|---|---|---|
| `landscape-1080` | 1920×1080 | как сейчас |
| `portrait-1080` | 1080×1920 | как сейчас |
| `epaper-5x3` | 800×480 | как сейчас, 1-bit подсказка |
| `landscape-4k` | 3840×2160 | стена / крупный ЖК |
| `square-1080` | 1080×1080 | меню-куб, соцсеть на экране |
| `bar-1920` | 1920×540 | полоса над стойкой |

Пресет по-прежнему query-параметр. Фон-прямоугольник на весь лист остаётся: у страницы Suika нет своего размера, PNG считается по содержимому (`presets.ts`).

**Безопасная зона — сделано.** Рамка 5% по умолчанию для ЖК и 8% для `epaper-5x3`, выключается в шапке. Рамка — оверлей вьюпорта, в `toJSON()` и в PNG её нет. Для e-paper рядом короткая подпись: на 1-bit выживут чёрный, белый и крупный шрифт.

**Бренд-кит — сделано.** При `mode=herald` редактор один раз читает `GET /api/brand-kit`. Четыре цвета показываются первыми в пикере заливки и обводки. Новый текст берёт `font_body` (шрифт заголовка стоит первым в списке). Если в ките есть `logo_content_id`, в стартовом листе (не в уже сохранённой бумаге) в углу лежит этот логотип. Ошибка кита не блокирует холст: остаются текущие дефолты.

**Шрифты — сделано.** В список шрифтов Suika попадают семейства из `server/lib/slide-fonts.js` (те же файлы, что уже отдаёт панель). `sans-serif` в новых макетах не использовать. Уже сохранённая бумага со старым `fontFamily` открывается как раньше.

**Картинка из библиотеки — сделано.** Рядом с «загрузить файл» — выбор изображения из контента текущего воркспейса (тот же отбор, что у пикера фона слайда: картинка, не виджет и не чужой sidecar). Байты вшиваются в бумагу так же, как локальный файл, чтобы PNG не зависел от того, удалят ли исходник. В sidecar хранится и `content_id` источника, чтобы при повторном открытии можно было заменить кадр.

Файлы: `herald/presets.ts`, `herald/api.ts`, пикер краски, тулбар картинки, `brand-prime` не трогать.

### Фаза B — галерея своих макетов

**Сделано.**

Первый экран `mode=herald` без `contentId`:

```
Новый дизайн
  [ Пустой ]  [ Из макета ]
                  │
                  ▼
         фильтр: все / альбом / портрет / e-paper
         карточка = превью PNG + имя + размер
                  │
                  ▼
         бумага клонируется (новые id), пресет = размер макета
```

Повторное открытие по `contentId` галерею не показывает.

**Где лежат макеты.** Каталог в репозитории, не в базе чужого сервера при установке:

`frontend-studio_v3/apps/suika/herald-templates/<id>/paper.suika`  
`frontend-studio_v3/apps/suika/herald-templates/<id>/thumb.png`  
`manifest.json`: `id`, `name`, `preset`, `tags`.

Сборка острова копирует каталог в `/suika/templates/`. Редактор читает его с того же origin. Сеть наружу не нужна (I4 для редактора: air-gap открывает галерею).

**Стартовый набор, 12 штук.** Рисуются в самом Suika, не генерируются кодом. Имена рабочие, состав можно сдвинуть, пока пак не влит:

| id | Пресет | Что на листе |
|---|---|---|
| `promo-hero` | альбом | плашка скидки, заголовок, срок, товар |
| `promo-portrait` | портрет | то же столбом |
| `announce-lobby` | альбом | заголовок, три строки, полоса снизу |
| `event-poster` | портрет | дата крупно, место, ведущий |
| `hours` | альбом | заголовок «сегодня», строки день/часы |
| `menu-photo` | альбом | фото слева, название, цена, состав |
| `menu-list` | портрет | шесть строк блюдо/цена |
| `staff-welcome` | альбом | фото, имя, должность |
| `wifi` | альбом | сеть, пароль, короткое пояснение |
| `safety` | альбом | три пункта, крупный заголовок |
| `epaper-notice` | 800×480 | заголовок и две строки, чёрное на белом |
| `bar-ticker` | 1920×540 | одна строка и акцентная плашка |

Тексты макетов — на русском и английском не двумя файлами, а одной бумагой с русским текстом-заглушкой. Локализация строк макета не входит в эту фазу: оператор заменяет текст на холсте.

Превью `thumb.png` снимается экспортом той же бумаги. В git лежит и JSON, и PNG превью. Если они разъедутся, карточка врёт — в проверке сборки хеш превью не обязателен, обязателен валидный `appVersion` `suika-editor_0.0.3` (как уже проверяет `server/test/suika-spike.test.js` для демо-файлов).

Клон макета выдаёт новые `id` узлов и новый `paperId`. Иначе два сохранения спорят за одну бумагу в `localStorage`.

### Фаза C — замок и шаблон команды

Два режима шапки, только в `mode=herald`:

| Режим | Кто | Что можно |
|---|---|---|
| Макет | тот, кто собрал дизайн | всё, включая замок |
| Заполнение | оператор филиала | текст и картинка у слоёв без замка; замок не снимается, слой не двигается и не удаляется |

Замок Herald — это не кнопка «замочек» Suika. Та остаётся временной блокировкой на сеанс. В атрибуты узла пишется `heraldLock: true`. Поле обязано пережить `toJSON()` / `setContents`. Узел с `heraldLock` в режиме заполнения рисуется без ручек resize/rotate.

Режим по умолчанию при открытии своего черновика — Макет. При открытии **шаблона** — Заполнение. Переключить на Макет может тот, кому Herald и так разрешает править контент воркспейса. Отдельной роли «только заполнение» в первой поставке нет: если у человека нет права записи в библиотеку, он и сохранить не может.

**Сохранить как шаблон.** Команда в шапке, видна в режиме Макет. Пишет JSON бумаги (без PNG-ролика) в новую таблицу:

`workspace_suika_templates`: `id`, `workspace_id`, `name`, `preset`, `paper_json`, `thumb` (маленький PNG в том же контент-хранилище или blob колонка — предпочтительно файл контента с пометкой, что это превью, не элемент плейлиста), `created_by`, `updated_at`.

Галерея фазы B показывает сначала шаблоны воркспейса, ниже — встроенные 12. Удаление шаблона не трогает уже созданные из него ролики: те хранят свою копию бумаги в sidecar.

Организационный пак (шаблон виден всем воркспейсам организации) — не в этой фазе. Колонка `org_id` в таблице не добавляется, пока нет UI организации.

### Фаза D — правка доезжает до экрана

Повторное сохранение уже заменяет строку `content` с тем же id (мост `bridge.ts`). Фаза D проверяет и дожимает хвост, а не придумывает новый протокол плеера:

- байты файла на диске меняются, `updated_at` контента растёт;
- плеер, у которого этот файл уже в плейлисте, получает его на следующем опросе так же, как замену загруженной картинки;
- имя ролика при повторном сохранении не переписывается на `Design ГГГГ-ММ-ДД.png`;
- если контент ждёт одобрения, замена идёт тем же путём, что замена из Studio (черновик одобрения, не обход). Это уже сделано для Studio в 6.3c; для `editor: suika` поведение должно совпасть, и на это нужен тест.

Отдельная кнопка «отправить на экран» не нужна. Экран берёт плейлист. Дизайн, который ни в один плейлист не положили, никуда не выйдет — это нормально и так написано оператору в тосте после первого сохранения.

**Несколько страниц.** Сейчас в библиотеку уходит текущая страница. В фазе D команда «Сохранить все страницы» создаёт по одному `content` на страницу (имена `Имя — 1`, `Имя — 2`) и не собирает плейлист сама. Сборка плейлиста остаётся в Плейлистах. Автоплейлист из страниц Suika легко сделать случайным вторым автором расписания — его нет в этом плане.

## 5. Чего план не делает

- Не рисует на холсте Suika часы, погоду, RSS, календарь и таблицу. Для этого есть виджеты и Слайды.
- Не отдаёт плеер JSON бумаги и не учит плеер шрифтам Suika. В файле уже растр.
- Не встраивает редактор iframe в дашборд. Окно `/suika/` остаётся.
- Не выключает Studio и не мигрирует старые `studio_designs` с `editor !== 'suika'` в новый формат.
- Не копирует макеты ScreenCloud, OptiSigns, Canva, PosterMyWall.
- Не обещает видео и анимацию на холсте. Ролик по-прежнему загружается в библиотеку как файл.
- Не добавляет multiplayer Suika (`apps/suika-multiplayer`, Yjs). Одновременное редактирование одной бумаги: последний `POST` побеждает, как сейчас у одного sidecar. Отдельная аренда — из плана слайдов (GAP-24), сюда не переносится, пока нет жалобы.
- Не кладёт шаблоны в подписанный каталог шаблонов панели (`/api/templates`). Тот каталог — виджеты и слайды с полями. Бумага Suika — другой формат.

## 6. Порядок и границы поставки

Фазы идут A → B → C → D. A и B дают ощущение Canvas без новой схемы БД. C добавляет таблицу. D почти без UI, если замена контента уже живая.

| Фаза | Готово, когда |
|---|---|
| A | **Сделано.** Новый дизайн открывается в одном из шести размеров. Цвета кита в пикере. Новый текст — шрифт каталога, кириллица видна. Картинку можно взять из библиотеки. Рамка безопасной зоны не попадает в PNG |
| B | **Сделано.** Без `contentId` сначала галерея. Двенадцать макетов открываются, правятся и сохраняются как новый ролик. Повторное открытие ролика галерею пропускает. Air-gap: галерея грузится с `/suika/templates/` |
| C | **Сделано.** Слой с `heraldLock` нельзя сдвинуть в режиме заполнения. «Сохранить как шаблон» появляется в галерее этого воркспейса и переживает перезапуск. Чужой воркспейс шаблон не видит |
| D | **Сделано.** Повторное сохранение не плодит второй файл и не переименовывает ролик. Экран с этим файлом в плейлисте показывает новый PNG после обычного обновления контента. Одобрение не обходится |

Проверка фазы A в браузере: библиотека → Создать дизайн → размер «полоса» → цвет из кита → картинка из библиотеки → сохранить → карточка в библиотеке → Изменить дизайн → те же слои. Плеер в этой проверке ещё не обязателен.

Строки галереи и режимов — `en` и `ru` в локали Suika (`apps/suika/src/locale`) и в `frontend/js/i18n`. Остальные языки панели падают в английский, как у остальных новых ключей.

## 7. Риски

| Риск | Что делаем |
|---|---|
| Бумага Suika обновится и старый `appVersion` не откроется | Макеты и sidecar остаются на `suika-editor_0.0.3`, пока ядро само не поднимет версию. `server/test/suika-spike.test.js` проверяет и демо-файлы, и каталог `herald-templates` |
| Шрифт есть в редакторе и отсутствует в PNG | PNG рисует браузер оператора. Шрифт каталога подключается `@font-face` до экспорта. Не полагаться на шрифт ОС |
