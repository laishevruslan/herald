# Data Sources, фаза 3 — готовые шаблоны слайдов

**Статус: 3.0 СДЕЛАНО (контракт + рендерер). 3.1–3.5 не начаты.**
**Родительский документ:** [`DATA_SOURCES_MASTERPLAN.md`](../DATA_SOURCES_MASTERPLAN.md), фаза 3.
**Намерение ветки:** остаёмся на текущем контракте слайда (`template` + `fields` + `{{ds:slug.field}}`). Новый runtime плеера не вводим.

Это план реализации шаблонов, которые человек без дизайнерского опыта может выбрать, привязать к календарю и опубликовать. Пишется против того, что есть в HEAD сегодня, а не против исходного RFC.

---

## 0. Зачем это нужно

Фазы 1–2 уже отгрузили движок: опрос iCal, кэшированный payload, подстановка в поля слайда, выбор переменных в дизайнере. Фаза 3 — то, что оператор реально видит. Конкуренты не продают «привяжи `{{ds:room.status}}`». Они продают **табличку на двери переговорки**, **повестку дня**, **календарную стену** — картинку, которую узнаёшь в галерее, и затем выбор источника.

Пока галерея не выглядит так, источники данных остаются фичей для тех, кто умеет в шаблоны.

Три шаблона из masterplan — правильные первые три. В нынешнем черновом виде их недостаточно.

## 1. Что уже есть в дереве

Честный инвентарь, чтобы работа была добавлением, а не переписыванием того, что только кажется неготовым.

| Часть | Где | Состояние |
|---|---|---|
| Payload iCal-резолвера (`status`, `status_detail`, `is_busy`, `current_*`, `next_*`, `event_N_*`, `agenda_text`) | `server/lib/data-sources/ical-resolver.js` | **Готово.** Есть алиасы (`next_title` = `next_event_summary`). Локализация через `locale` источника. |
| Подстановка `{{ds:slug.field}}` | `server/lib/slide-render.js`, `interpolateDataSources` | **Готово.** Отсутствующие ключи становятся `''`. `white-space:pre-wrap` уже сохраняет переносы в `agenda_text`. **3.0:** `hide_if_empty`, `show_when`, `bind_status`, `color_when`. |
| `__status` на resolveData | `getWorkspaceDataMapSync` / `attachSourceStatus` | **Готово (3.0).** `last_status` ряда не кладётся в iCal-payload. |
| `remaining_today_empty` / `remaining_today_count` | `ical-resolver.js` | **Готово (3.0).** |
| Модалка New Deck с тремя radio: blank / room / waste | `frontend/js/views/slides.js`, `openNewDeckModal` | **Черновик.** Список radio, без превью, без выбора источника. |

| `buildWasteCalendarSlide(slug)` | тот же файл | **Черновик.** Только 5:3. Жёлтый `#FACC15`. Немецкий текст. Slug угадывается по `abfall`/`waste` в идентификаторе. Варианта 1080p нет. |
| Daily Office Agenda | — | **Нет.** Резолвер уже отдаёт `agenda_text` и `event_0..N`. Ни один макет их не потребляет. |
| Тесты фабрик | — | **Нет.** Подстановка покрыта; JSON шаблона — нет. |
| Embedded-профиль 800×480 | `server/lib/embedded-profiles.js`, `seeed-reterminal-sticky` | **Готово.** Floyd–Steinberg, 1-bit. Шаблоны, где смысл несёт цвет, здесь его теряют. |

Пример PiP `Examples/PIP-Room-Status-Calendar/` — **параллельный продукт**: сам опрашивает ICS и шлёт web-overlay через POST. Фаза 3 его не заменяет; в справке новых операторов стоит направлять на Slides + Data Sources.

## 2. Конкурентный разбор — как шаблоны реально продают

Снято в сентябре 2026 по публичным документам и галереям. Утверждения ниже с источниками; где внутренности вендора проверить не удалось, это сказано.

### 2.1 Как отрасль это упаковывает (паттерн, не бренд)

Каждый серьёзный вендор делит **три продукта**, которые ScreenTinker сейчас пытается закрыть одним iCal-payload:

| Продукт | Типичный экран | Что выбирает оператор | Данные | Взаимодействие |
|---|---|---|---|---|
| **Табличка на двери / room sign** | планшет 7–15″ или e-paper, часто портрет | *тема* (светлая/тёмная, цвет бренда) | календарь одной комнаты | опционально QR / tap-to-book |
| **Schedule board** | ландшафтный ТВ 43–75″ в лобби | *мультикомнатный* макет | N календарей | опционально tap-to-book |
| **Agenda / calendar wall** | офисный ТВ 16:9 | тема-список или недельная сетка | один или несколько календарей | нет |

Вывоз мусора **не** является отдельным SKU у Yodeck, ScreenCloud, Xibo, OptiSigns, Appspace или Rise Vision. Это ниша DACH / facilities, которую ScreenTinker может выиграть *потому что* тот же iCal-движок уже умеет keyword-фильтры. Оставить, но не притворяться, будто у отрасли есть «галерея шаблонов для мусора».

### 2.2 По вендорам

#### Xibo (ближайший архитектурный родственник)

Виджет Calendar: на входе ICS URL, на выходе **Elements или Static Templates**. Данные кэшируются на плеере. Токены: `[Summary]`, `[StartDate]`, `[EndDate]`, `[Description]`, `[Location]`.

Решение, которое стоит скопировать: **альтернативный шаблон для «есть текущее событие» vs «событий нет».** У Xibo оператор ставит галочку «Set an alternative template for events that are current?» и получает другой HTML-блок, когда комната занята. Так они делают красный/зелёный без языка программирования в макете.

Xibo также стреляет **webhook на Current Event / No Event** (чтобы крутить LED-ленты). У ScreenTinker уже есть Triggers (`docs/triggers-design.md`). Не собирать это внутри слайда. Позже в справке можно написать: «чтобы мигнуть Philips LED, повесьте триггер на то же календарное условие» — вне фазы 3.

Xibo **не** отдаёт визуальную *галерею* переговорных. Оператор вставляет HTML. Это как раз тот разрыв, который ScreenTinker может закрыть.

#### Yodeck

Модель app gallery: «Calendar Events Feed» — это *приложение*, не слайд. Настройка: вставить ICS (можно несколько URL) → выбрать **Events Format** → **Color Theme** → шрифт → 12/24ч → интервал обновления → длительность в плейлисте.

Маркетинг конференц-комнат перечисляет: живая доступность, повестка дня, check-in / no-show, KPI в комнате. *Шаблоны* — тематические скины вокруг одного приложения, а не свободные слайды.

Вывод: мастер — это **тема + источник**, никогда не «вот JSON-шаблон, удачи». Несколько ICS на одном виде — это Schedule Board, не табличка на двери — отложить.

#### ScreenCloud

Отдельное приложение **Meeting Room**:
- список ближайших встреч *этой* комнаты;
- **цветовое состояние: оранжевый / идёт встреча, плюс «свободно снова в …».** Зелёный/свободно подразумевается;
- QR для брони;
- может стоять в плейлисте рядом с другим корпоративным контентом.

Отдельно — **digital wall calendar** для Outlook / Google / iCal. Meeting Room и Calendar Wall — разные приложения. Не склеивать их в один шаблон.

Вывод: цвет-как-состояние на LCD обязателен. QR на табличке у двери ожидаем. Бронь за QR — *другой продукт* (OAuth в Google/Microsoft). Честный QR у ScreenTinker: «открой ту страницу бронирования, которая у вас уже есть» — статичное поле URL, не двусторонний API.

#### OptiSigns

Приложение **Microsoft Meeting Room**: OAuth в M365, выбор N комнат, опционально «Allow Booking» (QR или касание). Выкатывается как ассет, элемент плейлиста или панель split-screen.

Вывод: мультикомната и живая бронь — платные фичи, завязанные на Microsoft Graph, не на ICS. Вне фазы 3. Сама *картинка* стены с несколькими комнатами всё равно валидный поздний шаблон (T4) через несколько `{{ds:room_a.status}}` на одном слайде — OAuth не нужен.

#### Appspace (корпоративный эталон для комнат)

Две карточки, не одна:

| Карточка | Устройство | Что показывает |
|---|---|---|
| **Room Schedule** | планшет у двери | одна комната: Available / Occupied / **Offline**; текущая + ближайшие; опционально бронь, check-in, продление, датчик занятости |
| **Schedule Board** | большой ТВ | много комнат, мгновенная бронь |

Темы выбираются визуально. *Идентичность* комнаты (имя, вместимость, оснащение, заметки) — это **свойства устройства** (`card.room.roomname`, …), а не запечённое в карточке — поэтому одну карточку ставят на 40 дверей, и каждая дверь знает свою комнату.

Что *можно* скопировать, не становясь Appspace:
- визуальный выбор темы;
- имя комнаты как **поле** (уже так), а не как slug источника;
- три визуальных состояния: свободно / занято / **устарело** (ошибка источника). Stale — то, что остальные называют Offline.

Что в фазе 3 копировать **нельзя**: мгновенная бронь, check-in, датчики занятости, Graph/GSuite OAuth. Это инвертирует модель источника данных (путь записи, секреты на плеере). Пометить как фаза 4+, если вообще когда-нибудь.

#### Rise Vision

Сотни шаблонов; calendar wall — флагман для образования. Оператор один раз привязывает Google/Outlook, и шаблон сам себя обновляет. Эта одноразовая привязка и есть вся продажа.

Вывод: «я привязал один раз» — метрика успеха нашего мастера. Если создание таблички занимает больше, чем: выбрать шаблон → выбрать календарь → назвать комнату → создать, мы проиграли.

#### Visix EPS / SyncSign (e-paper таблички на двери — реальные конкуренты 800×480)

Это не конкуренты CMS; это аппаратная категория, с которой конкурирует Sticky.

Типовой макет (ландшафт 7–13″, также портрет):
1. Имя комнаты, крупно, сверху.
2. Слово статуса или цветовая полоса (на 3-цветном e-paper: красный = занято; на 1-bit: инверсия панели или жирная чёрная полоса).
3. Название текущей встречи + «до какого часа» **или** явное AVAILABLE.
4. Следующие 3–6 встреч списком (время + название).
5. Опциональный QR, маленький, нижний угол.
6. Часы.

Правила дизайна, общие у всех, потому что e-paper — 1-bit (или 1-bit + красный):
- никакого серого body-текста, никакого циана, никакого жёлтого на тёмно-синем;
- кегль статуса ≥ ~32 px на 800×480; имена меньше, но всё равно жирные;
- без входной анимации (гостинг / цена полного refresh);
- кадр обновления — минуты, не секунды; наш интервал источника уже совпадает.

LCD-таблички у двери (LOOK DS и аналоги) добавляют **LED-ореол**: зелёный вдоль коридора, красный когда занято. Ореол со слайда не покрутить. Не имитировать его цветной линейкой 4 px на e-paper и не считать задачу закрытой; на LCD 16:9 полноростовая боковая полоса *и есть* этот ореол, и её стоит сделать.

#### Вывоз мусора / facilities (отдельного SKU нет)

Реальный паттерн муниципальных ICS (Abfallkalender, Recollect, Open Data немецких городов):
- следующая фракция **огромная** (Restmüll / Gelber Sack / Papier / Bio);
- дата как день недели + число;
- одна строка инструкции («выставить бак до 06:00»);
- затем: следующие 2–3 вывоза.

Цвет по фракции (жёлтый мешок, синяя бумага) работает на LCD и теряется на 1-bit. Вариант для e-paper: слово + опциональная иконка как 1-bit PNG, которую оператор кладёт сам, а не жёлтая заливка.

### 2.3 Что копировать, что пропускать

**Копировать (фаза 3):**
- галерея именованных шаблонов с превью — не список radio с описаниями;
- мастер: шаблон → источник → текст комнаты/заголовка → создать. Привязка один раз;
- табличка на двери и повестка — **разные шаблоны**, не один макет с опциональными полями;
- другой вид для занято vs свободно (два шаблона Xibo / цветовое состояние ScreenCloud);
- высококонтрастный 1-bit язык для e-paper 5:3 (Visix/SyncSign);
- боковая статус-полоса на LCD 16:9 (ореол LOOK DS, без LED);
- список ближайших 3–6 строк, не только «следующая»;
- имя комнаты как поле, которое оператор вводит сам, независимо от ICS-slug;
- текст пустого состояния, когда календарь свободен / нет следующей встречи (не показывать `Nächstes Meeting:  ()`);
- честность stale/error: если у источника `last_status=error`, слайд не должен выглядеть как «AVAILABLE».

**Пропускать (не фаза 3):**
- двусторонняя бронь, check-in, продление, occupancy (Appspace/OptiSigns);
- Microsoft Graph / Google OAuth. Остаёмся на опубликованном ICS;
- слияние нескольких ICS в одном приложении (Yodeck). Позже T4 может положить четыре slug на один слайд;
- LED / webhook из шаблона (Xibo). Использовать Triggers;
- недельная сетка calendar wall (Rise). Сначала список; сетка — другой язык вёрстки;
- живые HTML-темы, скачиваемые с маркетплейса.

## 3. Решения, которые фиксируют архитектуру

Это развилки. Менять их позже — значит мигрировать уже опубликованные деки.

### D1 — Шаблоны копируются при создании, а не живут связанными

Выбор «Meeting Room Sign» клонирует JSON слайда в новый дек. Правка галереи позже **не** переписывает существующие деки. Так после создания ведут себя static templates Xibo и карточки Appspace, и это единственная модель, которая не удивляет человека, который потом подвинул блок.

Галерея поэтому — **фабрика**, а не связанный мастер. Версионировать фабрику (`id` + `version`, опционально в `doc.template_id` дека), чтобы позже предложить «Сбросить макет до последней версии» — не делая это сейчас.

### D2 — Один слайд, а не дек состояний

«Альтернативный шаблон, когда событие текущее» у Xibo — два HTML-блоба. У нас два честных варианта:

| Вариант | Как | Цена | Вердикт |
|---|---|---|---|
| **A. Два слайда, условия плейлиста** | слайд «свободно» + слайд «занято», условие по тегу/метаданным на `is_busy` | Условия живут на элементах плейлиста, не на внутреннем состоянии слайда. Нужно, чтобы источник выставлял тег, который плейлист умеет фильтровать — он этого не делает. | Отклонить. |
| **B. Цвет/видимость из payload** | Рендерер кладёт `is_busy` / `status` на цвет бокса и опционально hide-if-empty | Маленько, локально в `slide-render.js`. Один слайд остаётся одним слайдом. | **Принять.** |

Конкретно фаза 3 добавляет два **opt-in, ограниченных** расширения к текущему словарю kind/style. Это минимум, чтобы догнать ScreenCloud/Xibo без языка шаблонов:

1. **`hide_if_empty: true`** на текстовом элементе. После подстановки, если поле пустое (или вся строка — только пунктуация/пробелы от `"Next: {{ds:x.next_title}}"`), элемент не эмитится. Ограничение: смотрим только собственный `fields[slot]` элемента, не соседние слоты. Пусто — это `trim()` подставленного значения равен `''`.
2. **`style.color_when`** (только box/rule/stat): `{ busy: '#B91C1C', free: '#15803D', stale: '#6B7280' }`. Рендерер читает `{{ds:slug.is_busy}}` из соседнего поля **или** новый `bind_status: 'slug'` на элементе. Предпочтительно **`bind_status: '<slug>'`** на элементе — он не занимает видимый слот. Разрешены только три hex-цвета. Неизвестно/отсутствует → цвет `free`, если только `resolveData(slug, 'last_status') === 'error'` или slug не резолвится → `stale`.

`is_busy` сегодня подставляется как `"true"` / `"false"` / `""`. Не парсить эту строку в CSS. Рендерер смотрит сырой кэш (функция `resolveData` уже возвращает нативное значение; `is_busy` в payload — boolean).

Шаблоны e-paper 5:3 **не используют красный/зелёный**. Они используют `busy: '#000000'` заливка + инвертированное слово статуса, `free: '#FFFFFF'` полоса с чёрным текстом, `stale: '#000000'` линейка 50%. Тогда 1-bit dither есть за что зацепиться.

### D3 — Варианты соотношения сторон — отдельные записи фабрики, не runtime-масштаб

`cqw` уже масштабирует кегль внутри кадра. Табличка 5:3, **перетёкшая** в 16:9 — другая композиция (слово статуса слишком мелкое, список слишком короткий). Конкуренты шлют разные карточки.

ID фабрик:

| id | Соотношение | Цель |
|---|---|---|
| `room-epaper-5x3` | `5:3` | Seeed Sticky / Waveshare 7.5″ 800×480 |
| `room-lcd-16x9` | `16:9` | планшет у двери / небольшой ТВ |
| `waste-epaper-5x3` | `5:3` | тот же e-paper |
| `waste-lcd-16x9` | `16:9` | лобби / кухонный ТВ |
| `agenda-lcd-16x9` | `16:9` | офисный ТВ, на 4K тоже нормально из-за `cqw` |

Портретная табличка `9:16` — случай планшета Appspace. **Не в фазе 3** — добавить `room-lcd-9x16` в 3.5, если попросит инсталляция Sticky-portrait или Fire-планшет. Форма фабрики должна это позволить без миграции (D1).

### D4 — Тексты фабрики — i18n, не немецкий

`buildRoomSignSlide` сейчас пишет немецкий в `fields`. Резолвер источника уже локализует `status` / `status_detail` из **`locale` источника**. Хром шаблона (`Next meeting:`, `Please put the bin out by 06:00`) должен следовать **языку дашборда** в момент создания (`t('slides.tpl.room.next_prefix')`), затем лежать в `fields` как обычный текст, который оператор может править.

Не привязывать хром через `t()` в момент рендера. Опубликованный слайд на стене — это не дашборд. После создания слова — данные.

### D5 — Выбор источника в мастере обязателен

Сегодня: первый slug или `testraum`. Получаются деки, чьи теги указывают на несуществующий источник, все поля пустые, и шаблон «выглядит сломанным».

Правило мастера:
- если в workspace есть источники: `<select>` имени + slug, обязателен для room/waste/agenda;
- если нет: основная кнопка — «Сначала подключить календарь» → `#/data-sources`, создание дека отменяется. Вторичная «Создать с placeholder `room`» допустима для дизайнеров, которые привяжут позже;
- шаблон waste предпочитает источник, чей slug или имя совпадает с `/waste|abfall|müll|trash|recycling/i`, но оператор подтверждает.

### D6 — Stale — полноценное состояние

`last_status === 'error'` не должен отображаться как AVAILABLE. Payload резолвера — последний *успешный* кэш; при ошибке fetch предыдущий `status: AVAILABLE` остаётся. Это правильно для 30-секундного сбоя и ложь через сутки.

Рендерер фазы 3 читает `resolveData(slug, '__meta_status')` **или** маршрут уже передаёт строку. Предпочтительнее расширить `resolveData` у вызывающих `slide-render.js`, чтобы отдавать `last_status` как зарезервированный ключ `__status` на том же slug, не кладя его в iCal-payload (чтобы поле `status` оставалось словом комнаты).

Реализация: `resolveData(slug, key)` уже может вернуть что угодно. Вызывающие в `routes/widgets.js` / embedded render передают `{ ...cached_data, __status: row.last_status }`. Шаблоны не биндят `__status` как текст. Его смотрят только `color_when` / `bind_status`.

### D7 — Кода плеера не добавляем

Шаблоны — обычные слайды. Android, web, Tizen, BrightSign, e-paper renderer едят их как сегодня. Motion на e-paper шаблонах — `animation: 'none'` (уже так). Шаблоны 16:9 могут использовать `slideU` с короткой задержкой — только LCD.

### D8 — Шрифты

Бандл слайдовых шрифтов — latin + latin-ext (`server/lib/slide-fonts.js`). Кириллица/CJK в `ROOM_STRINGS` упадёт на дефолтный шрифт панели. Не блокировать фазу 3 кириллическим паком. Не ставить `font: 'sans'` в ожидании, что Inter одинаково нарисует `СВОБОДНО` везде — не нарисует. Задокументировать.

## 4. Канонический контракт полей (что шаблонам можно биндить)

Резолвер уже эмитит больше алиасов, чем кому-либо нужно. Шаблоны биндят **только** этот набор, и тест его замораживает. Новые алиасы добавлять можно; эти имена переименовывать нельзя.

| Ключ | Тип | Смысл |
|---|---|---|
| `status` | string | локализованное слово BUSY/AVAILABLE |
| `status_detail` | string | «Свободно до 14:00» / «Занято до 15:30» / «Свободно весь день» |
| `is_busy` | boolean | сырое; для `bind_status`, не для показа |
| `current_title` | string | пусто, когда свободно |
| `current_time` | string | `09:00 – 10:00` или пусто |
| `current_organizer` | string | может быть пусто (приватность или в ленте нет) |
| `next_title` | string | пусто, если нет следующей |
| `next_time` | string | с датой (`Сегодня, 14:00` / `Завтра` / день недели) |
| `agenda_text` | string | список через перевод строки, уже `pre-wrap` |
| `event_{n}_title` | string | `n` от 0 до `max_events-1` |
| `event_{n}_time` | string | |
| `event_count` | number | подставляется десятичной строкой |
| `events_today_count` | number | |

**Не** биндить `status_de` / `status_en` в новых шаблонах. Они есть для старых деков. Режим приватности уже подменяет названия локальной маской «Busy» в резолвере — шаблоны не должны маскировать повторно.

Правило пустого поля: любой хром, который оборачивает токен (`Next: {{ds:x.next_title}}`), **должен** сидеть в слоте с `hide_if_empty: true`, и хром должен быть в том же поле, чтобы пряталась вся строка. Резать «Next:» (статика) и название (привязка) на два элемента только если оба прячутся вместе — проще оставить одно поле.

## 7. Форма кода

Не раздувать `slides.js`. Это уже редактор.

| Файл | Роль |
|---|---|
| `frontend/js/lib/slide-templates.js` | Чистые фабричные функции. `listFactories()`, `buildDeck(id, { slug, title, t })`. Без DOM, без `api`. |
| `frontend/js/views/slides.js` | Только модалка: вызывает фабрику, `POST /slide-decks`. |
| `server/lib/slide-render.js` | `hide_if_empty`, `show_when`, `bind_status` + `color_when`. Ограниченные enum. Тесты в `slide-render.test.js`. |
| `server/lib/data-sources/ical-resolver.js` | Добавить `remaining_today_empty` (и `remaining_today_count`, если полезно). Существующие ключи не переименовывать. |
| `server/test/slide-templates.test.js` | **Новый.** Либо тестировать фабрику через общий JSON-снимок, либо — если не хотим гонять frontend-модули в node без бандлера — дублировать фабрику как `server/lib/slide-templates.js`, а фронт ничего не импортирует и ходит в `GET /api/slide-templates` |

**D9 — где живёт фабрика.** Фронтенд — ванильные ES-модули без шага сборки (`CONTRIBUTING.md`). Node-тесты не могут `import` `frontend/js/lib/slide-templates.js`, пока раннер не грузит его как ESM и в файле при импорте нет `window`/`t()`. Это достижимо: фабрика принимает `t` аргументом, использует только инжектированный `uid`.

Предпочтительнее: **`frontend/js/lib/slide-templates.js` как ESM, тестируется `server/test/slide-templates.test.js` через маленький лоадер** (`node --experimental-vm-modules` уже так гоняет часть тестов) **или** JSON-снимок в `server/test/fixtures/slide-templates/`.

Самый простой путь в вкусе этого репозитория: **положить фабрику в `server/lib/slide-templates.js` (CJS)**. `GET /api/slide-decks/factories` возвращает `{ id, version, aspect, title_key, desc_key, thumbnail: { background, bars } }`. `POST /api/slide-decks` уже принимает `doc`. Добавить `POST /api/slide-decks { factory: 'room-epaper-5x3', data_source_slug, title, name }`, который собирает doc **на сервере**. Тогда модалка не разъедется с тестами, и PAT сможет выпускать табличку.

Это лучший шов:
- тесты вызывают `buildFactory('room-epaper-5x3', { slug: 'room', title: 'Berlin' })` и проверяют слоты + привязки;
- в дашборде нет чисел вёрстки;
- i18n хрома: серверу нужна локаль. `POST` берёт язык `req.user` или `Content-Language` / существующий i18n-заголовок, если он есть. Если у сервера нет локали дашборда пользователя, **присылать `locale` с клиента** (SPA её уже знает). Строки хрома живут в маленькой карте `server/lib/slide-template-copy.js` по тем же кодам, что `ROOM_STRINGS`, *или* клиент всё равно накладывает `t()` на хром после получения скелета.

Конфликт: в дашборде 10 языков; в `ROOM_STRINGS` 11. Третью таблицу не заводить.

**Принятое разделение:**
- **геометрия + привязки** на сервере (`server/lib/slide-templates.js`). Привязки всегда `{{ds:${slug}.…}}`;
- **строки хрома** заполняет клиент из `t()`, потому что именно там уже живёт `es.js`. Серверные тесты проверяют привязки и боксы, не немецкий vs английский хром;
- опциональный `POST` factory-эндпоинт приятен, но для 3.1 не обязателен. Клиент может оставить `POST /slide-decks` с клиентским `doc`, **если** `server/test/slide-templates.test.js` требует тот же модуль через `.cjs` дубль.

Чтобы не плодить две копии: **один CJS-модуль `server/lib/slide-templates.js`, отданный как `GET /api/slide-templates/:id/doc?slug=&title=`** (JWT, workspace-scoped только в том смысле, что slug не валидируется до publish). Клиент забирает скелет, затем перезаписывает поля хрома значениями `t()` по известным именам слотов (`note`, `next_label`, `headline`).

Имена слотов хрома (заморожены):

| слот | кто использует |
|---|---|
| `room_name` / `headline` | заголовок, который вводит оператор (после создания не i18n) |
| `next_meeting` | строка T1 с префиксом; клиент ставит префикс через t() при создании |
| `waste_note` | статичная инструкция T2 |
| `empty_hint` | T3 биндит `remaining_today_empty` — хром в резолвере, не в t() |

Значение поля T1 `next_meeting` при создании:

```
${t('slides.factory.next_prefix')} {{ds:${slug}.next_title}}  ({{ds:${slug}.next_time}})
```

плюс `hide_if_empty: true`.

### Чеклист изменений рендерера (`slide-render.js`)

`normalizeSlide` остаётся тотальным. Неизвестные ключи отбрасываются. Новые ключи:

```js
// on element (optional)
hide_if_empty: boolean,          // default false
show_when: 'always'|'busy'|'free'|'stale',  // default 'always'
bind_status: string,             // slug, max 64, /^[a-zA-Z0-9_-]+$/
color_when: { busy, free, stale } // each via existing color()
```

Порядок применения: подставить поля → посчитать статус из `bind_status` → пропустить элемент, если `show_when` не совпал → пропустить, если `hide_if_empty` и слот пуст → если `color_when` и kind это box/rule/stat, перекрыть `style.color` (и для stat цвет глифов: если фон перекрыт на соседнем box, собственный `color_when` у stat задаёт цвет текста).

Инверсия stat-на-box: два stat, `show_when: 'busy'` белый, `show_when: 'free'` чёрный, тот же бокс. Небольшая перерисовка допустима.

Безопасность: `bind_status` — slug, никогда не конкатенируется в HTML. Цвета по-прежнему проходят `color()`. Никакого нового CSS из строк источника.

### Call-site `resolveData`

Каждый вызывающий `renderSlideHtml`, который уже передаёт `resolveData` / `dataSources`, должен прикладывать `__status`. Grep: `routes/widgets.js`, `lib/embedded-render.js`, превью слайда в маршруте деков. Юнит-тест падает, если `__status` нет и `color_when` иначе покрасит `free` на строке с ошибкой.

## 9. Тесты (без них это протухнет)

| Тест | Что держит |
|---|---|
| ключи `CANON` есть на busy-фикстуре и на free-фикстуре | контракт D4/§4 |
| `remaining_today_empty` пусто vs фраза | T3 после обеда |
| hide_if_empty: поле `Next: {{ds:x.next_title}}` без следующей → элемента нет в HTML | баг `()` |
| show_when busy/free: из двух перекрывающихся stat присутствует только один | инверсия e-paper |
| color_when + `__status: error` → hex stale, не зелёный free | D6 |
| color_when + отсутствующий slug → stale, не free | fail-closed |
| фабрика `room-epaper-5x3` aspect `5:3`, motion везде `none`, цвета только `#000`/`#FFF` | 1-bit дизайн |
| привязки фабрики используют только ключи CANON | опечатка `next_event_title` (имя из masterplan, **не** основной ключ payload — алиасы включают `next_event_time`, но алиас названия — `next_event_summary` / `next_title`. **`next_event_title` нет.** Пример в masterplan врёт. Фабрики должны использовать `next_title`.) |
| подстановка фабричного слайда против SAMPLE_ICS в 09:30Z и 11:00Z | busy vs free end-to-end |
| существующий `slide-render.test.js` «правка поля оставляет макет byte-identical» остаётся зелёным | D2 не должен пересобирать template при смене данных — `color_when` это template, перекрытие цвета происходит на рендере из данных и HTML **меняется**. Это правильно и **нельзя** путать с инвариантом правки поля. Отдельный тест: смена `fields.room_name` не меняет число элементов/боксы. Смена `is_busy` в resolveData **меняет** цвет полосы. |

## 13. Риски

| Риск | Почему случается | Смягчение |
|---|---|---|
| Зелёная/красная полоса на Sticky становится шумом | 1-bit dither `#16A34A` | E-paper фабрика запрещает эти hex; тест сканирует JSON |
| `hide_if_empty` прячет `Next: {{…}}`, когда следующая есть, но время пустое | слишком жадная проверка пустоты | Пусто = trim слота после подстановки это `''` и только; строка с оставшимся префиксом всё ещё показывается, если только привязанный токен не составляет всё поле после interpolate — поэтому кладём префикс в поле и принимаем, что «Next:» с названием и без времени всё ещё видно. На T1 e-paper безопаснее одно `{{ds:slug.next_title}}` |
| `__status` забыли на пути рендера | новый вызывающий `renderSlideHtml` | тест, который грепает call site `renderSlideHtml(` и проверяет, что каждый передаёт обёртку resolveData — или хелпер `wrapDataSources(rows)` везде |
| Фабрика на клиенте разъезжается с тестами | две копии | 3.1 кладёт геометрию в `server/lib/slide-templates.js` |
| Немецкий хром на US-инсталляции | текущий черновик | D4, t() при создании |
| Режим приватности всё равно показывает организатора на T1 | шаблон биндит `current_organizer` | T1 фазы 3 организатора **не** биндит. Название уже маскируется в резолвере |
| Кириллический статус на latin-шрифте | §D8 | принять; Sticky сначала DE/EN |

## 14. Definition of done (фаза 3)

Оператор, который никогда не открывал JSON слайда, может:

1. Подключить опубликованный ICS Google/Outlook в Data Sources.
2. Slides → New → выбрать **Meeting Room Door Sign (e-paper)** или **(TV)** → выбрать этот источник → ввести имя комнаты → Create.
3. Опубликовать дек в плейлист, назначить дисплею.
4. Видеть AVAILABLE/BUSY (или FREI/BELEGT), обновляющееся на следующем интервале источника, без правки слайда.
5. То же для Waste (с отфильтрованным календарём) и Agenda (16:9).

Плюс: CI держит контракт полей, флаги рендерера и ограничение 1-bit цветов. Тогда чекбоксы фазы 3 в masterplan можно ставить.
